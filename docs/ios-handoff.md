# Cowlog：Mac開発への引き継ぎ

この文書は、別のMacでCodexとXcodeを使って開発を再開するためのものです。ソースの正本は [GitHubのCowlog](https://github.com/nanato0818/Cowlog) の `main` ブランチです。Windowsの一時フォルダや以前のZIPは参照せず、このリポジトリから始めてください。

## 目的と確定した範囲

- 牧場の牛に付ける首輪から届く位置・活動データを使い、関係者がiOSアプリで牛の状態を確認する。
- ユーザーの担当はアプリと、その表示に必要なデータの保存・読み取り。首輪や親機の電子工作は担当外。
- 想定経路は「首輪 → 牧場の親機 → API・データベース → iOS」。親機からの形式は[データ仕様案](data-contract.md)で、ハード担当との合意前。
- 第一段階の機能は、確認したい牛の優先一覧、最新位置の地図、日別移動経路、活動量、通信途絶・測定不足の表示。
- 優先表示は体調悪化の**可能性を確認する手掛かり**。病名や健康状態を確定しない。
- プッシュ通知、確認済み操作、観察メモは現段階では不要。機能を増やし過ぎず、動く試作の完成を優先する。期限は11月28日を前提にしない。

## リポジトリの現在地

| 場所 | 実装済みの内容 |
| --- | --- |
| `apps/mobile/Cowlog.swiftpm/` | iOS 17以降向けSwiftUIアプリ。サンプルモード、優先一覧、地図、個体別の日別経路・概算距離・活動量グラフ、HTTPS API接続設定。閲覧用トークンはKeychain保存 |
| `apps/api/app.py` | Python 3.11以降・SQLiteの試作API。測定記録の検証・保存、再送の重複排除、優先判定、アプリ用読み取りAPI |
| `apps/api/test_app.py` | 単体・HTTPテスト8件 |
| `apps/api/seed_demo.py` | サンプル用データベース生成 |
| `docs/data-contract.md` | 親機からAPIへ送るデータ形式の仮案 |
| `firmware/`、`hardware/` | 既存のハード側作業。首輪のGNSS検証コードはあるが、このアプリと実接続はしていない |

優先判定の現行ルールは試作値です。直近データが45分以上ない場合は通信途絶、直近2時間の測定量が足りない場合はデータ不足と表示します。測定が十分ある場合、ほぼ動きがない状態、または過去7日間の同じ時間帯からの大きな活動低下を「要確認」にします。牛ごとの基準が不足する間は「判定準備中」です。`apps/api/app.py` の `classify` が実装の正本です。

## 検証済み・未検証

- Windowsで `python -m unittest -q test_app.py` を実行し、8件成功。
- Swiftソースは構文解析済み。ただしWindowsにはXcodeがないため、**iOSアプリのコンパイル、シミュレータ・実機での動作は未検証**。
- 実機からの測定データ受信、クラウドへのAPI配置、HTTPS公開、利用者ごとの認証、App Store配信は未実施。
- GitHubにあるのはソースと文書。実データベース、秘密トークン、ビルド済みアプリは含めていない。

## Macでの再開手順

1. MacにXcode、Git、Codexを用意する。GitHubにアクセスできる状態で `git clone https://github.com/nanato0818/Cowlog.git` を実行する。すでにclone済みなら作業前に `git pull` する。
2. Codexでcloneした `Cowlog` フォルダを作業フォルダとして開く。この文書を最初に読ませる。
3. Xcodeで `apps/mobile/Cowlog.swiftpm` を開き、iOSシミュレータ向けにビルドする。開けない場合は `Package.swift` を指定する。最初のビルドで発生したエラーをCodexに渡し、同じリポジトリ内で修正する。
4. 起動できたら初期設定のサンプルモードで、優先一覧、地図、個体詳細、日別経路、活動量グラフを確認する。この段階ではAPIサーバーは不要。
5. API側は `cd apps/api && python3 -m unittest -q test_app.py` でテストする。ローカル起動方法は[APIのREADME](../apps/api/README.md)を参照する。アプリはHTTPS接続を要求するため、ローカルHTTP APIにはそのまま接続できない。
6. 作業結果を同じGitHubリポジトリにcommit・pushして、次の端末でも `git pull` で同期する。

## Macで最初に進める作業

1. Xcodeで実際にビルドできることを確認し、必要ならSwiftUIまたはプロジェクト設定を修正する。
2. シミュレータまたはiPhoneでサンプル画面の表示と操作を確認する。
3. 親機側との接続方式・送信項目を[データ仕様案](data-contract.md)に沿ってすり合わせる。
4. HTTPSのAPI配置先と利用者認証を決め、実データ接続を行う。

## MacのCodexに最初に渡す文

> GitHubのCowlogリポジトリをcloneした作業フォルダです。まず `docs/ios-handoff.md`、`README.md`、`docs/data-contract.md` を読んで現状を確認してください。次にXcodeで `apps/mobile/Cowlog.swiftpm` をiOSシミュレータ向けにビルドし、エラーがあれば修正してください。サンプルモードの画面を確認し、変更をこのリポジトリに反映してください。首輪ハードの実装や機能追加には進まず、既存の第一段階のアプリを動かすことを優先してください。
