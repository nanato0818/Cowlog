# 地図・GPSデバッグ

首輪のGPS位置が、アプリの地図（国土地理院の航空写真と醍醐牧場の5区画）のどこに載るかを確かめるためのローカルサイトです。判定はアプリと同じルール（精度100m超・座標なしは除外、1時間超の空白で経路を分割、15分超は古い位置）です。

## 起動

```bash
python3 tools/gps-debug/serve.py
```

http://127.0.0.1:8790 を開きます。Cowlog API の記録も見る場合は、閲覧用トークンを付けて起動します（トークンはサーバー側で付け、ブラウザには渡しません）。

```bash
COWLOG_READ_TOKEN=... python3 tools/gps-debug/serve.py --api http://127.0.0.1:8080
```

## できること

- **APIから読み込む**：個体と日付を選んで履歴を表示／全頭の最新位置
- **貼り付け・ファイル**：履歴・ダッシュボードのJSON、送信レコード（JSON Lines）、NMEA（GGA / RMC）、CSV（lat, lon 列）、首輪のシリアル出力（`Latitude :` / `Longitude:`）を自動判定
- **首輪をUSBで直接つなぐ**：Chrome / Edge のWeb Serialで受信しながら地図に表示
- **基準点**：地図クリック・座標入力・端末の現在地で正解の位置を置き、ずれの中央値・平均・95%・最大・平均のずれの向き・区画内の割合を表示
- **点の一覧**：時刻・座標・精度・区画・アプリでの使用／除外の理由。行かスライダーで点を選択

牧場で端末の現在地を使う場合、位置情報は `localhost` 以外では HTTPS が必要です。

## GPSのデバッグ手順

1. まず下のCSVを貼り付けて「読み込む」。赤い使用点2つと灰色の除外点1つが表示されることを確認する（架空データ）。

```csv
lat,lon,time,accuracy,device_id
34.33187762,133.17151134,2026-11-14T10:00:00+09:00,5,test
34.33190000,133.17155000,2026-11-14T10:00:10+09:00,8,test
34.33200000,133.17170000,2026-11-14T10:00:20+09:00,150,test
```

2. 実測は屋外の開けた場所で首輪を静止させて行う。地図の既知の位置を基準点に指定し、5〜10分のGPSログを読み込む。測量済み座標があるとより正確。住所の周辺中心を正解位置には使わない。
3. 「中央値」は普段のずれ、「95%」は大部分の点が収まる距離、「最大」は大きな飛び、「平均のずれ」は偏る方向。統計は読み込んだ有効点すべてが対象なので、静止試験ごとに「消去」し、複数の首輪や歩行ログを混ぜない。
4. 歩行試験では首輪を持って既知の道を歩き、経路が道沿いか、飛んでいないかを見る。固定基準点からの距離は歩行距離を含むためGPS誤差とは扱わない。
5. USBはMac/PCのChromeまたはEdgeで「接続」し、首輪を選ぶ。ボーレートはファームウェアに合わせる。シリアルモニターなど他のアプリは閉じる。これは閲覧端末に接続したUSBを読む機能で、公開元のMacのUSBをスマホへ転送するものではない。
6. AWS経路の確認はAPI中継を有効にして個体・日付を選び「履歴を表示」。USBでは見えるがAPIでは見えない場合、首輪→送信→AWS保存→APIの順に切り分ける。このサイトだけではAWSやファームウェアを修正しない。

注意：端末の現在地もGPS測定値であり正解を保証しない。「端末の現在地」は最初に得た位置を基準点に固定し、その後の青い端末位置のみ追跡する。NMEAのHDOPはメートルの精度ではない。精度不明の点も使用されるので「使用」＝高精度ではない。100m超は除外、時刻のない点は経路に結ばず、1時間超の空白で経路を分割する。読み込んだログは自動保存されないため、元のログを保存しておく。

## HTTPSで一時公開する方法（Macを起動したまま）

ターミナル1：

```bash
cd /Users/murakami/Desktop/Cowlog-Flutter
python3 tools/gps-debug/serve.py --port 8791
```

ターミナル2（Homebrewが導入済みの場合）：

```bash
brew install cloudflared
cloudflared tunnel --url http://127.0.0.1:8791
```

表示された `https://ランダムな名前.trycloudflare.com/?site=innoshima` をスマホで開く。
既存の8790と分けるため8791を使用。APIなしで始めれば首輪のAPI記録を外部公開せず、ファイル・貼り付け・現在地の確認ができる。
URLを知る人は誰でもアクセスできる。トンネルをCtrl+Cで終了すると公開終了。Macのスリープ中は使えず、再起動時にURLが変わる。Quick Tunnelはテスト向けで稼働保証はない。
API中継を有効にしたサーバーをそのまま公開すると、トークン自体は隠れていてもAPI記録を第三者が閲覧できるため、実データでの運用はログイン制限を付ける。

常設するなら、HTTPSの固定ドメインとログイン制限のあるホスティングを使う。ファイル/USBだけなら静的ホスティングでよいが、`serve.py` のAPI中継は動かない。API利用にはサーバー側の中継と認証が必要。Pythonの簡易開発サーバーを常設の公開サーバーとして使わない。

公式資料：
- https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
- https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API
