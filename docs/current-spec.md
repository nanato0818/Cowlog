## 2. 管理する番号とID

| 項目 | 現行の意味 |
|---|---|
| 表示番号 | 利用者がアプリで設定し、一覧・地図・詳細で見る番号 |
| 首輪固定ID | 首輪を区別する内部識別子。送信データの `device_id`。番号を変えても変更しない |
| 内部の履歴ID | APIの `id`。表示番号変更でも維持し、過去データへの参照を切らない |

- 新規保存できる番号は半角数字1〜12桁。例：`7`、`0007`、`123456`。
- 先頭の0を保存する。`7` と `0007` は別の番号として扱う。
- 入力前後の空白は除去する。英字・ハイフン・全角数字・空欄は保存できない。
- 同じ文字列の番号を別の首輪に重複して設定できない。
- 旧データに英字入りの番号がある場合は閲覧できる。新たにアプリから保存する場合は数字のみ。
- 旧DBの未装着登録に番号が残っている場合も重複チェックの対象。番号解放・削除の画面はない。
- 実データの件数は8頭固定ではない。デモの8件は画面確認用。多数台・長期運用の性能検証は未実施。

## 3. 番号を設定する操作

1. 「首輪・番号」を開く。
2. 固定IDを確認して対象の首輪の編集ボタンを押す。
3. 番号を入力し「保存」を押す。
4. 実データモードでは番号管理用の権限でAPIへ送信する。
5. サーバーが保存先・固定ID・番号を返し、アプリが応答を確認してから保存完了を表示する。
6. 一覧を再取得し、優先一覧・地図・詳細では新しい番号を使う。

番号変更時に位置・活動量の履歴は削除しない。最初の採番前に受信したデータも、新規の番号に対応付ける。

首輪一覧には、測定データを受信済みの固定IDと、既存登録の固定IDを表示する。新しい首輪がAWS側にまだ一度も現れていない場合、アプリだけで首輪を発見することはできない。手入力で未知の固定IDを新規作成する画面、Bluetooth探索、QR登録は設けていない。

番号未設定の新規首輪は、まず「首輪・番号」で設定する。番号を付けてから優先一覧・地図の対象になる。データ受信前でも旧管理コマンド等で登録されていれば、首輪一覧に表示される。

通信失敗時は保存成功と表示しない。送信後に応答だけが失われ、サーバー側では保存済みになる可能性はあるため、「一覧を再読み込みして確認」と案内する。同じ保存要求の再送で、既に同じ番号なら成功として扱う。

別端末が先に番号を変えた場合、取得時点の番号とサーバーの現在番号が違えば409で拒否する。重複番号も409。番号管理権限がなければ編集ボタンを無効にし、サーバーでも変更を拒否する。

## 4. 番号変更と、牛への付け替えの違い

現在の通常操作は「同じ首輪の表示番号を変更する」こと。例えば首輪Aの番号を0007から0020へ変えた場合、首輪Aの過去データも同じ履歴として表示する。

**別の牛へ首輪を付け替えて番号を変えても、アプリは牛の交代と判定して履歴を自動分割しない。** 個体台帳を持たないため、アプリだけでは同じ牛の番号変更と、別の牛への付け替えを区別しない。

旧個体台帳の情報・装着履歴・開発用CLIは、既存データを壊さないため内部に残している。旧データには過去の装着履歴に基づく履歴が含まれる場合がある。プロフィールの入力・閲覧画面はない。今回、既存DBの記録そのものは削除していない。

## 7. 詳細画面

- 番号、状態と理由、取得できる場合は電池残量・最新測定時刻・位置・測位品質を表示。
- 個体情報カードは削除。品種、生年月日、産次、分娩日、特徴、個体識別番号は表示しない。
- 日付を選び、その日の経路、測位点の時刻、概算移動距離、活動量の推移を確認。
- 日付選択範囲は2025年から端末の今日まで。DB上に保存されているデータのみ取得。
- 経路は有効な測位点を時系列で結ぶ。欠測・不適切な精度・1時間を超える空白では分割する。
- 移動距離は結んだ測位点間の距離の合計。実際の歩行距離の厳密な計測ではない。
- スライダーで経路上の測位時刻を選べる。
- 活動率は「動きのあった秒数÷測定できた秒数」。測定できなかった時間を無活動として扱わない。
- 過去7日の同じ時間帯から、必要な測定量を満たす3日以上がある場合、中央値と比較する。
- 詳細の比較対象は表示している記録の時間帯。一覧の判定対象は直近2時間なので、比較値は同じにならない場合がある。
- 詳細は開いた時・日付変更時に読み込む。30秒ごとに詳細の履歴や判定が自動で更新される仕様ではない。新しい一覧の状態を見るには戻って開き直す。

## 8. 状態判定の現在のルール

判定はサーバーで行う。画面側で病気や発情を診断する機能ではない。以下は現行の試作条件。

| 優先して確認する条件 | 表示 |
|---|---|
| 判定対象の測定記録がない | 未受信 |
| 最新の測定時刻が45分より前 | 通信途絶 |
| 直近2時間の測定可能時間が全体の70%未満 | データ不足 |
| 上記を満たし、直近2時間の活動率が1%以下 | 要確認 |
| 過去7日の同時間帯で70%以上測れている日が3日未満 | 判定準備中 |
| 比較可能で、直近活動率が基準の半分未満、かつ10ポイント以上低い | 要確認 |
| それ以外 | 通常 |

最新時刻はサーバー到着時刻ではなく、首輪の測定時刻。遅れて古い記録が届いても、新しく測定したようには扱わない。ダッシュボードは直近8日分の現在の装着期間の記録で判定するため、8日より古い記録だけの場合は「未受信」になる。長期の履歴は日付指定で別に読める。

中央値はソートした配列の中央要素を使い、偶数件のときは上側の中央要素を採る。活動集計は首輪から届く集計区間が重複せず、測定秒数が正しいことを前提にする。

USBのGNSS試作コードでは加速度を測定しておらず、活動測定時間0として送る。この場合、位置があっても活動量の要確認判定はできず、「データ不足」になる。GPSから活動量や電池残量を自動で作ることはしない。

## 9. AWSとの境界と必要なAPI

```text
首輪 --測定データ--> AWSの受信処理 --> 保存DB
                                      |
                                アプリ用HTTPS API
                                      |
                                Flutterアプリ

アプリ --番号設定--> AWS側の対応表（固定ID → 番号）
```

AWS側が以下のAPI契約を提供すれば、アプリはそのHTTPS接続先を指定して利用する。AWS上のDBへアプリが直接接続する構成ではない。

| API | 権限 | 用途 |
|---|---|---|
| POST `/v1/measurements` | 測定送信用 | 1〜100件の測定記録を受信する参考契約 |
| GET `/v1/dashboard` | 閲覧用 | 番号・状態・最新位置等を取得 |
| GET `/v1/cows/{id}/history?date=YYYY-MM-DD` | 閲覧用 | 内部履歴IDで日別データを取得 |
| GET `/v1/collars` | 閲覧用 | 番号未設定を含む首輪一覧 |
| PUT `/v1/collars/{device_id}/number` | 番号管理用 | 表示番号を保存 |

`cows` というAPIパスは旧版との互換性のため残している。個体台帳画面があるという意味ではない。

番号保存の本文は `{"number":"0007","expected_number":null}`。変更時の `expected_number` は取得済みの旧番号。成功応答は `{"device_id":"...","number":"0007","saved_to":"server"}`。

受信する主な測定項目は、固定ID、起動系列ID、通し番号、UTC測定時刻、緯度経度、精度（任意）、活動秒数、測定可能秒数、集計区間、電池残量（任意）、HDOPと衛星数（任意）。GPSが取れなかった回は座標を空にできる。

同じ固定ID・系列ID・通し番号の再送は二重保存しない。活動秒数 ≤ 測定可能秒数 ≤ 集計区間を検査する。首輪本体の通信方式がHTTPS以外なら、AWSの受信側でこの保存契約へ合わせる必要がある。現時点でMQTT等の方式を実装したわけではない。

## 10. 接続設定・通信エラー・保存

- 接続先や権限はビルド時に指定する。利用者向けのクラウドURL入力画面はない。
- `COWLOG_DEMO=false`、`COWLOG_API_URL`、`COWLOG_READ_TOKEN` を指定する。
- 番号編集を有効にする場合は別の `COWLOG_MANAGE_TOKEN` を指定する。
- 測定送信用トークンをアプリに埋め込まない。
- サーバー起動時、閲覧・送信・管理トークンが同じ値なら拒否する。
- 現在の固定トークンは試作用。一般配布用の利用者認証・失効可能なセッションは未実装。
- 一覧と履歴は取得成功時に端末キャッシュへ保存。通信例外等では保存済みデータを使い、通信不良を表示する。401などのHTTPエラーはキャッシュで成功扱いしない。
- 首輪一覧と番号保存はキャッシュへフォールバックしない。通信ができなければ番号編集用の一覧を取得できない。
- 番号保存後は古い一覧キャッシュを無効化する。古い一覧取得と番号更新が競合しないよう、一覧取得の終了を待ってから保存する。
- 通信タイムアウトは各要求20秒。自動で架空のデモデータへ切り替えない。
- 端末のタイムゾーン設定で日時を表示し、APIの日別履歴は日本時間の1日を返す。現在は日本時間に設定した端末での利用を前提とし、海外タイムゾーンでの日付整合は未対応。
- DBとアプリキャッシュは別。AWS側での保存期間、バックアップ、複数牧場の分離は未確定。
